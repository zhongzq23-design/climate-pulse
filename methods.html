Methods & definitions

Climate Pulse separates three kinds of information that can look similar on a map: source-reported hazard metrics, Climate Pulse-derived estimates or context, and local climate background. The default rule is source first: when GDACS or an upstream hazard system publishes a usable metric, Climate Pulse reports that value. An equivalent metric is calculated only when the source value is unavailable, and the result is explicitly labelled as derived.

How to read this page: the sections below explain how events enter the map, how hazard-specific metrics are selected, how derived quantities are calculated, and what each quantity does—and does not—mean.

1. How Climate Pulse chooses a metric

Climate Pulse does not recalculate the same quantity by default. For each metric, the project follows a fixed authority order:

structured GDACS / upstream metric → Climate Pulse fallback estimate → optional supplemental context

This order preserves both provenance and meaning. A source-first value can still be modelled rather than directly observed, so the interface distinguishes exposure, impact, proximity and derived estimates explicitly.

Exposed populationResident population spatially co-located with a physically defined hazard footprint. Exposure does not imply observed harm.
Proximity populationPopulation inside a separately labelled distance buffer around a hazard footprint. It is not interchangeable with primary footprint exposure.
Affected populationUsed only when a source reports an actual impact. It is not inferred from a polygon overlay.
Displaced populationUsed only for source-reported displacement or evacuation-type impacts.
Estimated population exposedA Climate Pulse-derived spatial estimate used only when the required footprint semantics are suitable and an upstream equivalent is unavailable.
Context populationPopulation inside a broad reported event/administrative area whose physical hazard coverage is not established; context is excluded from the exposure headline.

2. How events enter the map

The Standard Events backend is scheduled three times per day, at 00:17, 08:17 and 16:17 UTC. Each run checks NASA EONET, GDACS and Copernicus CEMS Rapid Mapping, normalizes source records into a common event structure and archives the resulting snapshot before downstream enrichment.

  • NASA EONET — event discovery and source metadata.
  • GDACS — disaster records, alert levels, mapped hazard/event geometry and hazard-specific impact or exposure resources.
  • Copernicus CEMS — emergency mapping activations and related source metadata.
Publication on Climate Pulse means that a record passed the current operational rules. It does not mean Climate Pulse independently verifies every statement made by the upstream source.

3. Event identity and deduplication

Source IDs and links are retained so an event can be traced back to its origin. For non-wildfire hazards, close records from different feeds can be treated as duplicates when they have the same hazard type and occur within the current spatial and temporal thresholds:

same hazard type AND distance < 80 km AND |date₁ − date₂| ≤ 5 days

Wildfires use a stricter identity rule. Distinct GDACS wildfire event IDs remain separate even when they occur near one another at similar times. A wildfire record is deduplicated only when an explicit shared identity shows that two records refer to the same event, such as a CEMS record that directly references the same GDACS ID.

4. Mapped footprints & population-exposure standard

Climate Pulse does not use one universal radius around every disaster to estimate exposed population. The primary method is hazard-specific spatial overlay: a physically meaningful hazard footprint is intersected with gridded resident population. This is consistent with the UNDRR concept of exposure as people or assets located in hazard-prone areas.

primary mapped exposure = hazard footprint × gridded resident population

When GDACS provides a usable polygon for a wildfire, tropical cyclone, drought or flood, Climate Pulse can show that geometry in the expanded event details. The browser map uses a topology-preserving simplified copy for readability, while Climate Pulse-derived spatial calculations use the unsimplified source geometry.

browser footprint = topology-preserving simplify(mapped source geometry)
derived spatial calculation = unsimplified mapped source geometry × reference dataset

Every reporting geometry has a semantic role. These roles are deliberately not interchangeable:

Exposure-gradeA physically meaningful hazard footprint suitable for direct population aggregation. Only this grade can enter the cross-hazard population headline.
Proximity-gradeA documented distance buffer used for a separate near-hazard measure. It never silently replaces primary footprint exposure.
Context-gradeA broad reported event/affected area, forecast envelope or otherwise insufficiently verified hazard geometry. Population inside it is context only.
Risk-gradeA hazard-risk or potential-impact footprint used for risk/crop context rather than a direct human-exposure claim.

A wildfire polygon is exposure-grade only after its GDACS/GWIS burned-area provenance, same-episode alignment and coarse area-integrity check have passed. A tropical-cyclone polygon qualifies only when its wind threshold and observed/actual temporal semantics are both explicit and machine-verifiable. Current generic GDACS wind-labelled cyclone polygons are context-grade until that validation is available. GDACS flood polygons are context-grade reported event/affected areas, not observed inundation extent. Drought polygons are risk-grade, not confirmed human impact or crop loss.

The periodic-report headline Unique mapped population exposed is calculated from the spatial union of public/significant exposure-grade footprints before GHSL extraction. Geographic overlap is counted once:

Unique mapped population exposed = GHSL population inside UNION(all eligible exposure-grade footprints)

Wildfire geometry that fails admission QC, context-grade flood areas, unverified tropical-cyclone polygons, proximity buffers and risk-grade drought areas are excluded from that headline. The metric is spatially deduplicated mapped exposure, not verified tracking of unique affected individuals.

Fail-closed rule: if the physical meaning of a geometry is ambiguous, Climate Pulse keeps it out of the primary exposure headline. A hazard type or keyword is not sufficient evidence by itself: wildfire geometry must pass source and episode QC, and for tropical cyclones the word wind alone is not sufficient evidence of a specific threshold or observed status.

The canonical policy is maintained in Population Exposure Standard v1.2 ↗.

5. Wildfire: perimeter exposure after admission QC

GDACS forest-fire events are supplied by the Global Wildfire Information System (GWIS). GDACS documents the GWIS near-real-time burned-area product as using MODIS and VIIRS active-fire information to define individual wildfire perimeters and estimate burned area. Climate Pulse therefore uses a GWIS perimeter as the primary wildfire exposure concept, but the event type alone is not enough to make a polygon exposure-grade.

For each GDACS wildfire, Climate Pulse first reads the current GDACS episode and its GWIS impact resource. Burned area and population exposure are kept aligned to the same GDACS/GWIS episode so a card does not mix metrics from different wildfire updates. The population fields are modelled exposure, not observed harm.

POPAFFECTEDPopulation exposed in the burned area; equivalent to SUMPOP0.0. Climate Pulse treats the perimeter/burned-area value as the primary wildfire exposure concept.
SUMPOP1.0Population within 1 km of the burned area; proximity metric.
SUMPOP2.0Population within 2 km; proximity metric.
SUMPOP5.0Population within 5 km; proximity metric. OECD (2022) documents a 5 km wildfire-buffer methodology for population exposure, but Climate Pulse keeps this separate from the primary cross-hazard headline.
SUMPOP10.0Population within 10 km; proximity metric.

Before a mapped wildfire polygon can contribute to the cross-hazard population headline, Climate Pulse requires four pieces of evidence: GDACS/GWIS source provenance for the burned-area metric, the same GDACS/GWIS episode for the burned area and footprint, a valid source-reported burned-area value, and a coarse area-integrity check between the mapped polygon and that source value.

wildfire exposure-grade admission = GDACS/GWIS provenance + same episode + valid burned area + 0.5 ≤ mapped area / source burned area ≤ 2.0
Area-integrity boundary: the factor-of-two range is a deliberately broad corruption/semantic guard, not an uncertainty interval. A mapped/source difference above 25% is retained as a warning even when the polygon still passes. Missing provenance, episode mismatch or a gross area mismatch causes the geometry to fail closed to context-grade.

If the corresponding GDACS/GWIS primary population field is unavailable, Climate Pulse can estimate population inside a wildfire perimeter with JRC GHSL 2025 only when that geometry itself has passed the admission gate. The fallback is labelled as a Climate Pulse-derived estimate and never silently replaces a source value.

fallback primary wildfire exposure = GHSL population inside QC-admitted wildfire perimeter

This perimeter-based primary exposure follows the same basic spatial concept used by Modaresi Rad et al. (2023), who define primary human exposure as population residing within large-wildfire perimeters.

Wildfire identity and wildfire visibility are separate rules. Nearby wildfire IDs are not merged. For display, Orange and Red GDACS wildfires remain visible, while a Green wildfire must satisfy both current thresholds:

burned area ≥ 10,000 ha AND population within 5 km ≥ 10,000

The 5 km value in this display rule is a screening/proximity criterion; it is not promoted into the primary cross-hazard population headline. MODIS forest overlap is retained only as supplemental spatial context and is not labelled as confirmed forest loss.

6. Tropical cyclones: advisory exposure first, geometry fails closed

For GDACS tropical cyclones, Climate Pulse reads the current episode's advisory timeline and prefers the current/actual advisory entry when available. Structured advisory population values remain useful source-modelled event-level exposure; they are kept separate from the spatially deduplicated cross-hazard headline unless a corresponding mapped geometry passes the stricter exposure-grade gate.

pop39Raw GDACS timeline field retained for traceability. Climate Pulse does not interpret the numeric suffix as a 39-kt scientific threshold; the documented GDACS population-exposure method uses a 34 kt wind buffer.
pop74Raw GDACS timeline field retained for traceability. Climate Pulse does not interpret the numeric suffix as a 74-kt scientific threshold; the documented GDACS population-exposure method uses a 64 kt wind buffer.
popstormsurgePopulation in the modelled storm-surge zone. It is a separate source/model exposure metric and does not certify a wind polygon.
actual / currentDescribes the advisory timeline entry. It does not by itself prove that a separate mapped polygon is an observed wind footprint.

For a mapped tropical-cyclone polygon to enter the cross-hazard population headline, it must explicitly identify a supported wind threshold—currently 34 kt or 64 kt—and must explicitly establish observed/actual rather than forecast or unspecified temporal semantics. The geometry must also be a wind polygon rather than a generic event area, centre-distance buffer, storm-surge area or mixed impact polygon.

TC exposure-grade = explicit wind polygon + (34 kt OR 64 kt) + observed/actual semantics
Current implementation: the existing GDACS polygon selector can identify wind-labelled geometry, but a generic wind-labelled polygon such as gdacs_wind_polygon does not prove the exact wind threshold or whether the polygon is observed rather than forecast. It is therefore context-grade and excluded from the cross-hazard headline.

If a future extractor can verify these properties, it may persist an explicit method such as gdacs_observed_wind_34kt_polygon or gdacs_observed_wind_64kt_polygon. Only such validated geometry can be promoted to exposure-grade. Forecast wind envelopes, generic event-polygon fallbacks and EONET-only 300-km centre-proximity screens remain context/screening only. Orange and Red GDACS storms can still remain visible even when their mapped geometry is not headline-eligible.

A World Bank/GHSL GDP exposure proxy may also be shown as supplemental context. It is not a replacement for GDACS human-exposure metrics and is not an estimate of economic loss.

7. Drought: threshold/risk context, not crop-loss claims

GDACS drought classification draws on the Global Drought Observatory (GDO) and its agricultural drought risk/impact framework. When GDACS publishes an agricultural drought impact/risk area, Climate Pulse reports that source value first.

The public label is intentionally “Agricultural drought potential-impact/risk area”. It should not be interpreted as failed-crop area, crop-loss area or confirmed agricultural damage.

The current drought integration does not provide the same structured population-exposure fields that Climate Pulse uses for wildfire and tropical cyclone. Climate Pulse therefore does not manufacture an “affected population” from a drought polygon.

MODIS land/forest overlap and FAO CROPGRIDS crop physical area can be added as supplemental spatial context:

supplemental crop overlap = Σ CROPGRIDS crop physical area inside mapped drought risk/impact geometry

If a future drought human-exposure metric is added, it must use an explicit, documented hazard threshold or risk definition over a defined time scale, then intersect that threshold footprint with population. An arbitrary circular buffer around an event centre is not the primary method.

Green droughts keep the compact display focused on source severity/risk and mapped context. Orange and Red events may show additional asset context. A Red event can show a Human impact section, but values appear only when a reliable source provides them; any Climate Pulse-derived population estimate must be labelled Estimated population exposed.

8. Flood: inundation exposure vs reported-area context

For floods, source-reported human impacts take precedence over any Climate Pulse spatial screening. The preferred spatial definition of flood exposure is population inside a physically mapped inundation footprint, without adding a generic event-centre buffer. Tellman et al. (2021), for example, estimate population exposure using satellite-observed flood inundation.

primary flood exposure = population inside validated inundation footprint

Current implementation: when GDACS provides usable flood geometry, Climate Pulse treats it as a reported event/affected-area context polygon, not as an observed inundation map. It therefore remains context-grade and does not enter the cross-hazard exposure headline.

Before retaining that context polygon, Climate Pulse performs a source-feature selection QC. It keeps one GDACS polygon feature aligned to the reported event coordinate and suppresses the footprint when no candidate lies within 75 km. This prevents unrelated polygon resources from being blindly unioned.

What this QC does not do: center-alignment only checks that the selected source feature is plausibly associated with the reported event. It does not establish inundation. Very large selected reported areas are explicitly warned as context and must not be interpreted as flooded land area.

A future satellite-observed or otherwise physically explicit inundation product can be promoted to exposure-grade only after source-specific quality control and explicit persistence of its geometry semantics. Climate Pulse will not reinterpret the current GDACS reported-area polygon as inundation simply because it is available.

A population or GDP calculation made from the reported event area describes what lies inside that mapped context; it does not establish that every person, asset or location within the polygon was flooded.

Climate Pulse may calculate a country-split GDP exposure proxy from the mapped flood event area, GHSL 2025 population and World Bank WDI 2024 GDP per capita:

GDP exposure proxy = Σcountry [GHSL population in mapped flood event area × WDI 2024 GDP per capita]
This is supplemental context, not economic loss. It does not replace source-reported fatalities, displacement, affected population, asset damage or business interruption.

9. Reference datasets for fallback and context

Climate Pulse uses external reference datasets only when they serve a defined fallback or contextual role. They do not silently overwrite an equivalent upstream hazard metric.

Population fallbackJRC GHSL GHS-WUP-POP R2025A, epoch 2025, approximately 1 km. It represents gridded resident population, not real-time human presence.
Land / forest contextNASA MODIS MCD12C1.061, 2024, 0.05°, IGBP sub-pixel class percentages.
Crop contextFAO CROPGRIDS v1.08, 2020, 0.05°, crop physical area.
GDP contextWorld Bank WDI NY.GDP.PCAP.CD, 2024 GDP per capita in current US$.
The interface identifies whether a displayed value is source-reported/modelled, a Climate Pulse-derived fallback, proximity screening, or supplemental context.

10. Local climate comparison

The climate panel compares a location's historical same-calendar-month climate with a short recent weather-context window. It is designed to answer how recent conditions compare with historical climate normals at this location. It does not attribute an individual event to climate change.

Historical normals use CRU-TS v4.10 on the 0.5° global land grid. Climate Pulse extracts the nearest valid CRU land cell; when an event coordinate is offshore, the backend can use the nearest valid land cell within 500 km and reports that distance. The recent IFS value is sampled at the same comparison coordinate.

Early climate1901–1930 same-calendar-month CRU normal.
Modern normal1981–2010 same-calendar-month CRU normal.
Recent 7-dayMean across seven consecutive fully elapsed ECMWF IFS 0–24 h short-range forecast windows from the same UTC cycle hour.
DroughtTemperature + precipitation + VPD
Wildfire / HeatTemperature + precipitation + VPD
Flood / Storm / LandslideTemperature + precipitation
Recent does not mean observed. The seven-day column is constructed from IFS short-range model forecasts whose full daily valid windows have elapsed. It is weather context, not a station or reanalysis observation.

11. Same-month normals and recent 7-day operators

The two historical columns use the calendar month containing the end of the recent seven-day window. For example, a window ending in September is compared with the 30 Septembers in 1901–1930 and the 30 Septembers in 1981–2010.

Historical temperature30-year mean of the CRU monthly mean temperature for the selected calendar month.
Historical precipitation30-year mean monthly precipitation total divided by the mean number of calendar days in that month, reported as climatological mm/day.
Historical VPD30-year mean of monthly VPD calculated from CRU monthly mean temperature and actual vapour pressure.
Recent temperatureMean of seven complete daily temperature means; each daily mean uses 3-hourly IFS values with trapezoidal time weighting over forecast hours 0–24.
Recent precipitationSum of seven complete daily 0–24 h IFS precipitation accumulations divided by 7, reported as mm/day.
Recent VPDMean of seven daily mean-state VPD values; each day uses its mean temperature and mean actual vapour pressure derived from 3-hourly dew-point temperature.
Recent precipitation (mm/day) = Σ(seven daily 0–24 h totals) / 7

Using seven complete days reduces sensitivity to a single wet or dry day and avoids comparing an instantaneous daytime/nighttime value with a monthly climate normal. It does not remove all sampling variability, especially for precipitation.

12. VPD calculation

Vapour pressure deficit (VPD) is the difference between saturation vapour pressure (SVP) and actual vapour pressure (AVP). Higher VPD generally indicates greater atmospheric evaporative demand.

VPD = SVP − AVP
SVP = 6.1078 × exp(aT / (T + b))   [hPa]

For T ≥ 0°C, a = 17.269 and b = 237.3. For T < 0°C, a = 21.875 and b = 265.5.

For historical CRU normals, AVP comes from monthly vap and SVP is calculated from monthly mean temperature. Monthly VPD is calculated first and then averaged across the 30 years in each normal period.

For the recent IFS column, AVP is calculated from 2 m dew-point temperature at each 3-hour step. Climate Pulse forms a daily mean AVP and daily mean temperature, calculates SVP(daily mean T) − daily mean AVP, and then averages those seven daily VPD values.

VPD is related to relative humidity (RH):

RH = 100 × AVP / SVP   [%]
VPD = SVP × (1 − RH / 100)
Temporal-resolution limitation: historical CRU VPD is based on monthly means, whereas the recent IFS operator preserves 3-hourly information when constructing each daily mean. The two columns are useful climate-context comparisons, not identical sampling distributions.

See Zhong, Z., Chen, H.W., Dai, A. et al. (2025), “Sub-diurnal asymmetric warming has amplified atmospheric dryness since the 1980s,” Nature Communications 16, 8247 ↗.

13. Climate context is not event attribution

The comparison describes local background climate and recent modelled weather context. A warmer, drier or higher-VPD recent week at an event location does not, by itself, show that anthropogenic climate change caused that event.

Formal event attribution requires separate, event-specific evidence and is treated as a distinct information layer. Climate Pulse therefore keeps event detection, source impact/exposure metrics, Climate Pulse-derived fallback/context, local climate comparison and formal attribution conceptually separate.

14. Main limitations

  • GDACS event records, episodes, mapped polygons and impact resources can change as an event evolves.
  • GDACS/GWIS wildfire and tropical-cyclone population values are modelled exposure, not observed harm.
  • Wildfire population enters the cross-hazard headline only when the mapped geometry passes GDACS/GWIS provenance, same-episode and coarse area-integrity QC; the factor-of-two area check is an operational integrity guard, not a measurement-uncertainty estimate.
  • Current generic GDACS tropical-cyclone wind-labelled geometry is excluded from the cross-hazard headline until both an explicit 34-kt or 64-kt threshold and observed/actual status are machine-verified.
  • Different hazard polygons have different meanings; a flood reported-area polygon is not equivalent to an observed inundation map, a forecast wind envelope is not equivalent to an observed wind footprint, a proximity buffer is not equivalent to a primary hazard footprint, and a drought risk area is not confirmed crop loss.
  • Only explicitly exposure-grade geometry enters the cross-hazard population headline; context-grade, proximity-grade and risk-grade areas are excluded.
  • Browser footprints are simplified for display; Climate Pulse-derived spatial calculations use unsimplified source geometry.
  • The non-wildfire proximity rule is an operational cross-source deduplication heuristic; source IDs and links are retained for traceability.
  • Gridded residential population does not represent real-time human presence.
  • Forest and crop overlap describe spatial context, not ecological damage, crop failure or yield loss.
  • The GDP indicator is a country-level per-capita exposure proxy and does not represent observed economic loss or within-country economic concentration.
  • CRU-TS is land-only; offshore events may use the nearest valid land cell within the configured search distance.
  • Historical CRU monthly normals and a recent seven-day IFS mean have different temporal sampling and spatial resolution.
  • IFS recent values are model forecasts, not observations; model error can affect temperature, humidity and precipitation.
  • Precipitation is intermittent. A seven-day average is more stable than one day but can still differ strongly from a 30-year monthly climatological daily rate.
  • CRU-derived VPD from monthly mean temperature omits sub-daily temperature variability.
